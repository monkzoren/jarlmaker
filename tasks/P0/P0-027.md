## Goal
A core table declaration says whether clients may subscribe to it. Today `defineTable` has no visibility field, so P0-009's generator emits `public: true` for every table, which would expose server-only tables (the purchase ledger, wallets, anything with private state) to every client. After this task a table is private unless its declaration says `public: true`, and the generated SpacetimeDB table carries exactly that flag.

## Definition of done
- [ ] `defineTable` accepts an optional `public: boolean` (default `false`), carried on `TableDef`; `tables.test.ts` covers the default and an explicit `true`
- [ ] `tools/gen-tables` emits `public: <flag>` from the declaration instead of a constant `true`; the fixture (`test/fixture.ts`) has one public and one private table and `test/fixture.generated.ts` is regenerated
- [ ] Changing visibility is not an append-only violation (it is not part of the manifest's column layout); a test proves it
- [ ] `packages/core/src/store/README.md` "Declaring a table" shows the field
- [ ] `pnpm build`, `pnpm lint`, `pnpm test` green locally

## Notes
Found while building P0-009: CLAUDE.md 3.6 subscribes spatial tables by sector window, so tables like `entity_pos` must be public, while 3.5.12's `purchase` and `player_wallet` must not be. Row-level visibility (chat, P6-003) is a separate, later mechanism. A task that registers the first client-subscribed table (e.g. `entity_pos`) must set `public: true` once this lands.
