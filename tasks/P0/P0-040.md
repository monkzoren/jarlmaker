## Goal
The client's reconnect timings live in tuning like every other number (CLAUDE.md 3.1 pillar 3): the backoff floor and ceiling between reconnect attempts, how long a connect attempt may hang, and how long the client waits with no server traffic before it treats a silent socket as dropped. P0-016 ships them as named constants in `packages/client/src/net/reconnect.ts` (`RECONNECT_TIMING`) because the `net` schema is core's and outside its touches.

## Definition of done
- [x] `netTuning` in `core/src/kernel/net.ts` gains `reconnectBackoffMinMs`, `reconnectBackoffMaxMs`, `reconnectSilenceMs`, `reconnectConnectTimeoutMs` (positive ints, max >= min), each with a doc comment
- [x] `content/tuning/net.ts` sets them to P0-016's values (500, 5000, 3000, 8000) with a comment on intent
- [x] `core/src/kernel/net.test.ts` covers the new keys, including a refusal for max < min
