## Goal
Packages outside `core` that run on the test host (`tools/replay`, later `tools/balance` and the quest solver) can import `MemoryStore`, `MemoryStoreOptions` and `createRng` from `@bastion/core`. P0-005 built them but could not export them: `src/index.ts` was outside its `touches`.

## Definition of done
- [x] `packages/core/src/index.ts` exports `MemoryStore`, `type MemoryStoreOptions` and `createRng` (met via the Notes option: a separate `@bastion/core/testing` entry, `src/testing.ts` + `package.json` `exports`; `index.ts` points to it)
- [x] `store/README.md` gains a short "MemoryStore" section: constructor options (`seed`, `now`, `tables`) and the test-host controls (`setNow`, `advance`, `events`, `clearEvents`)
- [x] A test imports `MemoryStore` via the package entry (`../index.ts`) and round-trips one row (`src/testing.test.ts` imports `@bastion/core/testing`, so it also exercises the `exports` map)
- [x] `pnpm -r typecheck` and `pnpm -r test` green

## Notes
MemoryStore is a fixture and is never shipped (CLAUDE.md 3.4); the client bundle must not import it. If a separate `@bastion/core/testing` entry is preferred to keep it out of the main barrel, that is an equally valid way to meet the first DoD line (update `package.json` exports then, and add it to `touches`).
