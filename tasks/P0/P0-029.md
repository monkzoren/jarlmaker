## Goal
The entity system (P0-008) is part of the game every host runs: `@bastion/core` exports it, importing core registers its tables, commands and tuning sections, `core.tick` runs its movement tick, and the generated server schema carries its tables with the right visibility.

## Definition of done
- [ ] `packages/core/src/index.ts` re-exports `./entity/index.ts`, so `tableList()` includes `entity`, `entity_pos`, `entity_input`, `entity_seq`
- [ ] `SYSTEM_TICKS` in `tick.ts` has `entityTick` as its first entry (the slot its comment reserves), and the entity tick stamps events with the kernel's tick number from the tick context (P0-025) instead of 0
- [ ] `entity` and `entity_pos` are declared `public: true` (P0-027); `entity_input` and `entity_seq` stay private
- [ ] Core tests that build a Game with empty tuning (`createGame({ tuning: {} })`) still pass once the movement/world tuning sections are always registered (they pass a fixture tuning or a local registry)
- [ ] `pnpm --filter @bastion/gen-tables gen` run and `packages/server/src/tables.ts` committed; `pnpm build` (drift check) green
- [ ] `pnpm build`, `pnpm lint`, `pnpm test`, `pnpm contentlint` green locally (contentlint no longer warns that `tuning.movement` / `tuning.world` are unvalidated)
