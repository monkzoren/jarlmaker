## Goal
The server package documents and guards the BUILD_ID that P0-019 stamps: the
README lists `build-id.ts` (generated, git-ignored) and the public `build_info`
view, and publishing or generating bindings from inside `packages/server`
stamps a fresh id exactly like the root scripts do, so no module ever goes out
with a stale or missing id.

## Definition of done
- [ ] `packages/server/README.md` file table lists `src/build-id.ts` (generated by `tools/build-id`, git-ignored) and the `build_info` view, with the `SELECT * FROM build_info` command in "Run it locally"
- [ ] `packages/server/package.json` `server:publish` and `server:bindings` run under `node ../../tools/build-id/src/cli.ts --`
- [ ] A test in `packages/server/test` asserts `src/index.ts` exports `build_info` and imports `BUILD_ID` from `./build-id.ts`
- [ ] `pnpm build lint test tasks:validate` green

## Notes
Discovered while working on P0-019: its `touches` did not cover the server
README or package scripts, so it wraps only the root `server:publish` /
`server:bindings`. Running `pnpm server:publish` from `packages/server`
publishes whatever `build-id.ts` the last root build left (or fails when there
is none). See `tools/build-id/README.md`.
