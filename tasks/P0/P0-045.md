## Goal
`packages/core/src/entity/budget.test.ts` still enforces the 2 ms tick budget
(CLAUDE.md 3.4), but ordinary scheduler noise on a shared CI runner or a busy
laptop no longer fails it. Today it asserts the mean of a single 200-tick
batch against 2 ms, and it has failed at 2.02 ms (CI run 36413230535 on PR
#41, which does not touch core) and at 2.19 ms locally with Docker running.

## Definition of done
- [x] The test times several batches of ticks and asserts the minimum per-tick batch time against the unchanged 2 ms budget (the 2 ms target and the 200-player walking setup are unchanged)
- [x] The batch count is a named constant next to `TICKS`, with a comment explaining why the minimum is used
- [x] `pnpm build lint test tasks:validate` green

## Notes
Proposed patch in https://github.com/monkzoren/jarlmaker/pull/41#issuecomment-5868593392.
Using the minimum over repeats is the usual way to keep noise out of a CPU
budget: interference only ever adds time, so the fastest batch is the closest
to the code's real cost. Other `budget.test.ts` files added later should
follow the same pattern.
