## Goal
When the server rejects the stored auth token (for example after the local
SpacetimeDB data volume was wiped, so its signing key changed), the client
forgets that token and reconnects as a fresh identity on its own, instead of
retrying forever with `dropped: Failed to verify token: Unauthorized`.

## Definition of done
- [x] A connect error that is a token rejection (401 / "Failed to verify token") clears the stored token for this `tokenKey` and the next attempt connects without one
- [x] Any other connect error keeps the token (a network drop must never change identity)
- [x] Unit tests for both cases in `packages/client/src/net/`
- [x] `pnpm build lint test tasks:validate` green

## Notes
Discovered while working on P0-022. Reproduced: connect with `?profile=a`,
`pnpm server:down`, `docker volume rm bastion_bastion-stdb`, `pnpm server:up`,
`pnpm server:publish`, reload: the pip shows
`dropped: Failed to verify token: Unauthorized` until the
`bastion.token.bastion.a` localStorage key is removed by hand. The README
(P0-022) documents the manual fix meanwhile. Token handling lives in
`net/token.ts` and `net/connection.ts` (`onConnectError`).
