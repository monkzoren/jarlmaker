## Goal
A worker filing discovered work runs `pnpm tasks:new --phase P0 --lane core --title "…"`. It gets a task file whose id is unused on `main` and on every remote branch, so two parallel workers can no longer file the same id (this happened with P0-023 in wave 2).

## Definition of done
- [ ] `tasks:new` fetches `origin`, collects every task id present on `origin/main` and on every `origin/*` branch (reusing `tools/tasks/src/git.ts` helpers), and picks the next free number in the phase
- [ ] It writes `tasks/<phase>/<id>.md` in the Section 4.2 format (all frontmatter keys, `status: todo`, `## Goal`/`## Definition of done`/`## Notes` placeholders), with `--lane`, `--title`, `--system` (defaults to the lane), `--discovered-by` (defaults to the task claimed on the current branch, if any), and `--depends-on` options
- [ ] It adds the new id to the phase's `<phase>-EXIT` `depends_on`, so `tasks:validate` stays green
- [ ] `--local` skips the fetch and prints a warning that ids are only checked against the working tree
- [ ] `tasks:validate` reports ids that collide between `main` and any remote branch when run with `--remote`
- [ ] Unit test for id allocation; git integration test (bare origin, two clones) proving that two branches filing concurrently get different ids once the first has pushed
- [ ] Root script `tasks:new`; `tasks/README.md` step 5 tells workers to use it instead of hand-picking ids
- [ ] `pnpm build lint test tasks:validate` green
