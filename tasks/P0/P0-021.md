## Goal
The two remaining architecture-police rules: numeric literals in `core` rules and ticks must come from tuning, and the server may never iterate a whole table.

## Definition of done
- [x] `no-tunable-literal`: fails numeric literals other than 0, 1, -1 in `packages/core/src/**/rules.ts` and `**/tick.ts`, allowing array index access and `// tunable-ok: <reason>` escapes that the reviewer checks
- [x] `no-tick-scan`: fails `.iter()`, `.count()`, and full-table iteration on `ctx.db.*` handles in `packages/server/src/**` outside an explicit allowlist file
- [x] RuleTester tests for both rules; `pnpm lint` green on `main` with them on
- [x] `pnpm build`, `pnpm lint`, `pnpm test` green locally

## Notes
In `core` the `Store` type already makes scans impossible. This rule guards the host glue.
