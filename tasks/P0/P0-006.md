## Goal
`core.execute(game, store, sender, envelope)` validates and runs one Command through a registry; `core.tick(game, store, dtMs)` runs each system tick in the fixed order documented in `tick.ts`; emitted events are dispatched to registered handlers in the same transaction. Duplicate commands from a reconnecting client are rejected by `(sender, nonce)` (3.6.7).

## Definition of done
- [x] Command registry: systems register `{kind, schema, handle}`; unknown kinds and schema failures return a `Rejection`, never throw inside core
- [x] Nonce dedupe: a `command_nonce` table (pk sender) stores the last accepted nonce; a nonce ≤ last is rejected with code `duplicate`
- [x] Event dispatch: systems register handlers by event `kind`; handlers run after the command/tick step that emitted them, in registration order
- [x] `tick.ts` holds the one ordered list of system ticks, with a comment per entry
- [x] Tests: unknown command, bad payload, duplicate nonce, out-of-order nonce, handler ordering, tick order
- [x] `pnpm build`, `pnpm lint`, `pnpm test` green locally
- [x] Reviewer checks: no file over 600 lines, no numeric literal other than 0/1/-1 in `rules.ts`/`tick.ts`, no store scan, nothing imported from `server`/`client`

## Notes
Hosts throw on a `Rejection` so the reducer transaction rolls back (3.4 Hosts); `core` itself returns rejections as values so tests can assert them.
