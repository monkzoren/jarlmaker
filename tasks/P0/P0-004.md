## Goal
The `@bastion/core` package exists with the contracts every other system builds on: the `Store` interface (CLAUDE.md 3.4, no scan), the table declaration format (Zod row schema + declared indexes, typed so `byIndex` only accepts declared indexes), the `GameEvent` and `Command` unions as extensible registries, and the `Game` context that carries injected, validated content.

## Definition of done
- [x] `packages/core` package (`@bastion/core`, ESM, strict, `noUncheckedIndexedAccess`) with no runtime deps other than `zod`
- [x] `store/types.ts`: `Store`, `TableName`, `Row<T>`, `IndexOf<T>`, `IndexVal<T,K>`, `Id`, `Timestamp`, `Rng` exactly as in 3.4; there is no `scan` or iterate-all method
- [x] `store/tables.ts`: a `defineTable({ name, row: z.object(...), pk, indexes })` helper and an (initially empty) `TABLES` registry; a type test (`expectTypeOf`) proves `byIndex` rejects an undeclared index name
- [x] `events/index.ts`: `GameEvent` base shape `{kind, tick}` and a pattern for systems to add members; `commands.ts`: `CommandEnvelope {nonce: number, cmd}` and `Rejection {code, message}`
- [x] `game.ts`: `createGame(content)` returns the `Game` context passed to `execute`/`tick`; `core` never imports `@bastion/content`
- [x] `docs/DECISIONS/0005-content-injection.md` records why content is injected (ADR 0004 item 5)
- [x] README for `store/` and `events/` explains the contract in under a page
- [x] `pnpm -r typecheck` and `pnpm -r test` green locally (lint and turbo may not exist yet)

## Notes
Contract task: interfaces, types and docs only, no MemoryStore (P0-005) and no execute/tick logic (P0-006). Keep the table DSL small: it must also drive `pnpm gen:tables` (P0-009), so prefer plain data (`pk: "id"`, `indexes: [{name, columns}]`) over clever types.
