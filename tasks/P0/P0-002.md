## Goal
`pnpm lint` runs ESLint (flat config, typescript-eslint) over every package, with a local plugin `@bastion/eslint-plugin` that enforces the layout rules from CLAUDE.md 3.3 and 3.5.9.

## Definition of done
- [ ] `tools/eslint-plugin` package with rules `max-file-lines` (fails at 601 lines, any file type ESLint sees), `layering` (`packages/core/**` may not import `pixi.js`, `spacetimedb`, `@bastion/server`, `@bastion/client` or any relative path outside `packages/core`), and `no-emoji` (fails on Unicode pictograph ranges in `packages/client/**` and `packages/content/**` strings, comments and templates)
- [ ] Each rule has RuleTester tests with at least one valid and one invalid case per behavior
- [ ] Root `pnpm lint` runs the rules across the repo and is green on `main`
- [ ] A throwaway 601-line file makes `pnpm lint` fail (paste the output in the PR)
- [ ] `pnpm build`, `pnpm lint`, `pnpm test` green locally

## Notes
`no-tunable-literal` and `no-tick-scan` are P0-021, because they need real `core`/`server` code to aim at. The cosmetics import-direction rule (3.5.12) arrives with the P6 cosmetics contract.
