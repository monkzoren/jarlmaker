## Goal
The first real system, built to the full folder template (3.3): players join, get an `entity` row and a narrow `entity_pos` row, and move by a `move` Command whose input the tick integrates with the single pure `step` function that the client will reuse for prediction.

## Definition of done
- [x] Folder template complete: `README.md`, `HOWTO.md`, `schema.ts`, `rules.ts`, `tick.ts`, `commands.ts`, tests
- [x] Tables: `entity` (wide: kind, def, owner, level, …) and `entity_pos` (narrow: x, y, vx, vy, facing, sector) with an index on `owner` and on `sector`
- [x] `step(pos, input, dtMs, world)` is pure, cell-collides against a `WorldView.walkable(cx, cy)` interface (flat, always walkable in P0), and computes `sector` from tuning
- [x] Commands `player.join` (idempotent per sender) and `entity.move` (input vector, clamped, validated as hostile)
- [x] Event `entity.sector_changed` is emitted when a step crosses a sector boundary
- [x] Determinism test: the same input sequence gives bit-identical positions across two MemoryStores and a direct `step` loop
- [x] `pnpm build`, `pnpm lint`, `pnpm test` green locally
- [x] Reviewer checks: no file over 600 lines, no numeric literal other than 0/1/-1 in `rules.ts`/`tick.ts`, no store scan, nothing imported from `server`/`client`

## Notes
Movement numbers (speed, accel) come from `content/tuning/movement.ts` through the `Game` context. Collision against real terrain arrives in P1 (P1-006), and only the `WorldView` implementation changes.
