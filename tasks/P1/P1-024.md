## Goal
The `world` tuning section (`chunkSize`, `sectorSize`) is registered by the world system that owns it, not by the entity system's P0 stand-in, and sector keys have one definition.

## Definition of done
- [ ] `registerTuning('world', ...)` and its `TuningRegistry` entry live in `core/src/world/schema.ts`; `entity/world-view.ts` no longer registers it
- [ ] `entity`'s `sectorOf` produces the same key as the world contract's `SectorKey` conversion (one delegates to the other, or a test asserts they agree over a grid of points including negatives)
- [ ] `entity/README.md` tuning table names `world` as the owner
- [ ] `pnpm build`, `pnpm lint`, `pnpm test` green locally
- [ ] Reviewer checks: no file over 600 lines, no numeric literal other than 0/1/-1 in `rules.ts`/`tick.ts`, no store scan, nothing imported from `server`/`client`

## Notes
Found while building P0-008: movement computes `sector` from `tuning.world.sectorSize`, but no world system existed in P0, so `entity/world-view.ts` registered the section. If P1-001 registers it too, `createGame` throws "tuning section \"world\" is already registered", so this should land with or right after P1-001. `entity/world-view.ts` is the adapter P1 is allowed to edit (P1-006 Notes).
